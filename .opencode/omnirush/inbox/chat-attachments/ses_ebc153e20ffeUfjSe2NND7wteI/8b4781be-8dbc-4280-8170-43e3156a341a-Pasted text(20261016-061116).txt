## Round 1 — what was delivered

### Goal
A **manager-facing leak investigation tool** that profiles the CSVs, builds a verified field mapping, joins safely, computes transparent metrics, flags up to three money leaks with deterministic rules, and lets a manager reach **one evidence-backed action** in ≤3 clicks.

### Stack & structure
Python + Streamlit + pandas + Altair (as recommended by the PRD §7).

| Path | Responsibility |
|---|---|
| `app.py` | Data load, session state, sidebar, layout |
| `leaklab/profile.py` | CSV inspection, type parsing, concept→column mapping + validators |
| `leaklab/model.py` | Safe left joins from the transaction grain + join health |
| `leaklab/metrics.py` | Metric definitions, availability, INR formatting |
| `leaklab/rules.py` | 5 deterministic leak rules → `Alert` / `RuleStatus` |
| `leaklab/views.py` | Design system: KPI strip, alerts grid, charts, panels |
| `.streamlit/config.toml`, `assets/` | Light theme, vector brand mark + favicon |
| `selftest.py`, `test_app.py`, `test_edge.py` | Pipeline, headless UI, robustness tests |

### Schema-first ingestion (no hard-coded column names)
All 5 files profiled and mapped by **name hints + type validation** (keys near-unique, dates parse, amounts numeric):

| File | Rows | Role | Mapping quality |
|---|---|---|---|
| `transactions.csv` | 18,000 | transactions | 11 concepts mapped |
| `products.csv` | 250 | products | cost, list price, category |
| `customers.csv` | 3,000 | customers | region, segment |
| `inventory.csv` | 5,000 | inventory | on-hand, reorder threshold |
| `campaigns.csv` | 1,200 | campaigns | spend, clicks, conversions |

**Join health:** 0% unmatched on product & customer keys; grain preserved at 18,000 rows. `campaigns` shares **no key** with transactions → reported independently, no fabricated attribution.

Net realized revenue **₹79,07,358** · cancellation rate **9.4%** · return rate (fulfilled) **9.3%** · discount rate **8.3%** · products at reorder point **34**.

### 1. Deepen diagnosis (stay non-causal)

### 2. Recover value, not just flag it
- Quantify **recoverable** vs total leak with confidence ranges; rank actions by expected recovery.
- Replenishment recommendations with expected recovered revenue and lead-time assumptions.

### 3. Move from alerts to a workflow
- Assign owner, set a validation metric, track recovery **realised vs predicted** over time.
- One-page exportable brief (PDF) per leak for stakeholder review.

### 4. Guardrailed attribution (upgrades the Round 1 "no attribution" stance)

### 5. From deterministic rules to assistive detection
- ML/anomaly detection for revenue and margin leaks as a **second opinion** alongside the deterministic rules; forecasting only where it adds decision value.
- Full profit/margin accounting *only* after resolving the synthetic cost-basis inconsistency, with the flag retained.

### 6. Platform hardening
- Thresholds/config via YAML + UI; data-contract validation; scheduled refresh; persistence (DB); auth/roles; deployment; performance & caching at scale.
